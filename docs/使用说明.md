# Deskrawl 内存管家

把 Deskrawl 的内存占用**由你说了算**：拖一根滑杆，它就再也涨不过那条线。

- 单文件 exe，绿色免安装，双击即用（不是安装包，也不写系统目录）
- 自动识别 `Deskrawl.exe`，游戏重启后自动重新接管
- 三种管控方式，从"温柔"到"硬核"任选
- 实时曲线 + 一键体检，告诉你内存到底花在哪
- 不需要 Python、不需要 .NET SDK，Win10/Win11 自带的运行时就能跑

> 想先搞明白**为什么它这么吃内存**，看 [Deskrawl内存分析.md](Deskrawl内存分析.md)。

---

## 一、跑起来

1. 双击 `DeskrawlMemGovernor.exe`。
2. 如果右下角出现「以管理员身份重启」，**点它**。
   普通权限只能看不能改，Windows 不允许跨进程改别人的内存配额。
3. 启动游戏。程序会自动接管 `Deskrawl.exe`，左边卡片里出现进程名和 PID。
4. 拖「内存上限」滑杆（或点数字直接输入，例如 `4096`），然后点 **应用上限**。

完事。之后游戏再怎么加载资源，常驻内存都会被压在红线以下。

## 二、界面怎么看

```
┌─ 目标进程 ──────────── 自动识别 Deskrawl.exe，点「切换」可改管别的进程
├─ 内存上限 ──────────── 滑杆决定它能占多少；点数字可精确输入
├─ 管控方式 ──────────── 三种策略，默认第一种
├─ 应用上限 / 解除限制 / 立即回收
├─ 常驻 / 提交 / 余量 ── 三张实时卡片（绿条=占用 RAM 比例）
├─ 内存走势 ──────────── 蓝=常驻，橙虚线=提交，红虚线=你设的上限
└─ 内存体检 ──────────── 点「分析原因」，拆开它的内存构成，给建议值
```

底部状态栏：`自动接管`（游戏重启后自动重新套用上限）、`开机守护`（登录后自动启动本程序）。

## 三、三种方式怎么选

| 方式 | 你在游戏里会感觉到 | 什么时候用 |
|---|---|---|
| **工作集上限（推荐）** | 几乎无感，偶尔读盘轻微卡一下 | 日常都用这个 |
| **上限 + 定时回收** | 每 20 秒可能顿一下，常驻更低 | 内存实在紧张，后台还开着浏览器 |
| **提交硬上限（有风险）** | 超了直接闪退 | 强制自律，知道自己在干什么 |

**建议值（16 GB 内存）**：日常 4～6 GB；只玩游戏 8 GB；小地图低画质 3 GB。
**别低于 1.5 GB**，Unity 加载资源需要这么多，压太狠会疯狂读盘反而更卡。

## 四、命令行（可选）

```bat
DeskrawlMemGovernor.exe --cli list
DeskrawlMemGovernor.exe --cli stat     --pid 1234
DeskrawlMemGovernor.exe --cli apply    --pid 1234 --limit 4096 --mode cap
DeskrawlMemGovernor.exe --cli apply    --pid 1234 --limit 4096 --mode trim
DeskrawlMemGovernor.exe --cli release  --pid 1234
DeskrawlMemGovernor.exe --cli snapshot --pid 1234 --out 报告.txt
DeskrawlMemGovernor.exe --cli watch    --name Deskrawl.exe --limit 4096 --interval 3
```

- `--limit` 单位是 MB。
- `--mode`：`cap` 工作集上限 / `trim` 上限+回收 / `commit` 提交硬上限。
- `watch` 适合做成开机任务：一直守着，游戏一启动就接管。

## 五、常见问题

**Q：设了上限，游戏会崩吗？**
工作集上限不会。它只是把不常用的页换到硬盘，游戏要用时再读回来。可能卡顿，不会崩溃。
「提交硬上限」才会让游戏闪退——那是它的设计目的。

**Q：任务管理器里为什么还显示提交很大？**
提交 ≠ 常驻。提交是"预约"，工作集才是"真占着 RAM"。你真正要压的是后者，本工具压的也是后者。

**Q：回收之后立刻又涨回去？**
说明游戏正在活跃使用这批内存（加载新地图）。这时上限会自动把它们挡住，不需要反复点回收。

**Q：改了没反应 / 提示权限不足？**
用管理员身份运行。Windows 不允许普通权限改别人的进程配额。

**Q：想彻底不管了？**
点「解除限制」，或者直接关掉本程序（关掉后上限自动失效，因为配额句柄跟着进程走）。

**Q：配置存在哪？**
exe 同目录的 `deskrawl-mem.conf`；如果目录不可写，会退到 `%APPDATA%\DeskrawlMem\config.conf`。
开机自启写在 `HKCU\Software\Microsoft\Windows\CurrentVersion\Run\DeskrawlMemGovernor`，取消勾选「开机守护」即删除。

## 六、它到底做了什么（技术细节）

| 能力 | 用的 Windows API |
|---|---|
| 工作集硬上限 | `SetProcessWorkingSetSizeEx(h, min=1, max=cap, QUOTA_LIMITS_HARDWS_MAX_ENABLE)` |
| 立即回收 | `EmptyWorkingSet(h)` |
| 提交硬上限 | `CreateJobObjectW` + `SetInformationJobObject(JobObjectExtendedLimitInformation, JOB_OBJECT_LIMIT_PROCESS_MEMORY)` + `AssignProcessToJobObject` |
| 降低回收优先级 | `SetProcessInformation(ProcessMemoryPriority, VERY_LOW)` |
| 内存构成体检 | `VirtualQueryEx` + `QueryWorkingSetEx` + `EnumProcessModulesEx` + `GetMappedFileNameW` |

几个实测得来的细节（写在这里免得后人踩坑）：

- `SetProcessWorkingSetSizeEx` 的 min 必须 > 0，传 0 会返回 `ERROR_INVALID_PARAMETER`；传 1 字节即可。
- 解除上限用 1 TB 或 `QUOTA_LIMITS_HARDWS_MAX_DISABLE`，但**工作集不会自动涨回去**，要等游戏自己再访问。
- `AssignProcessToJobObject` 对已运行的进程要 `PROCESS_SET_QUOTA | PROCESS_TERMINATE`，只给查询权限会 `Access Denied`。
- 进程已经在一个作业里也能再加入（Windows 8+ 支持嵌套作业）。

## 七、自己编译

系统自带 .NET Framework 4.x 就能编，不需要装 SDK：

```bat
build.cmd
```

源码在 `src\`：`Core.cs`（进程/配额/体检）、`Ui.cs`（自绘控件与主题）、`MainForm.cs`（界面）、`Program.cs`（入口与 CLI）。

## 八、边界（说清楚免得误会）

- 它管的是**工作集与提交**，不改游戏内部逻辑；游戏想申请多少还会申请，只是超出的部分被换到硬盘。
- 它不减少硬盘里的资源包，也不修 Unity 的 GC 行为。
- 上限对**单个进程**生效。游戏、助手、Steam 各自独立，想一起管就在「切换」里逐个接管。
- 如果哪天游戏更新后进程名变了，用「切换」手动选一次即可。
